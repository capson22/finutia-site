Compatible connected servers

Extend Finutia through MCP without pretending every tool is built in.

MCP, or Model Context Protocol, is a standard way for other software to offer tools to an AI assistant. A compatible server can extend what Finutia can reach beyond its built-in connectors.

The important distinction

Finutia did not write the tools on a server you connect. It keeps their origin visible and treats the server's description as the server's own claim—not as a guarantee from Finutia.

How a connection works

  1. You provide the compatible server address and, optionally, a label you recognize.
  2. Finutia validates and protects the address before connecting. If the server requires authorization, the consent happens through its sign-in flow.
  3. Finutia discovers the tools the server offers and stores a pinned list for your account.
  4. Those tools can then appear in your assistant's conversations under the server that provided them.

What happens when tools change

A tool is added

A server review reports and pins the newly offered tool instead of silently blending it into an old list.

A tool changes

Finutia reports the changed definition. The tool is not automatically disabled merely because its description or schema changed.

A tool disappears

A tool the server withdraws stops being offered to the assistant until the server provides it again.

Credentials and approval

Server addresses can contain secret information, so Finutia treats them as credential material: they are validated, encrypted, and kept out of ordinary activity text. OAuth tokens are also encrypted. Calls to connected-server tools flow through Finutia's approval system, where your Auto, Manual, or Bypass setting and applicable rules determine whether the action pauses.

MCP expands the toolset; it does not erase the trust boundary.

You can see which server supplied a tool and review what that server currently offers.
